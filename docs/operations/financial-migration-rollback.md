# Rollback финансовой миграции этапа 5A

Миграцию `20260803000000_financial_hardening` нельзя применять без успешного
запуска `ops/backup/pre-migration-postgres`.

## Условия rollback

Rollback требуется, если миграция не завершилась, Prisma обнаруживает drift,
финансовые snapshot-поля заполнены некорректно или контрольные E2E-тесты не
проходят.

## Процедура

1. Остановить backend и запретить новые импорты.
2. Зафиксировать логи и идентификатор неуспешного deploy.
3. Создать отдельную копию текущей повреждённой базы для анализа.
4. Поднять чистую PostgreSQL той же версии.
5. Проверить `SHA256SUMS` из pre-migration backup.
6. Проверить архив командой `pg_restore --list`.
7. Восстановить архив только в чистую базу.
8. Выполнить Prisma validate и проверить таблицу `_prisma_migrations`.
9. Проверить пользователей, офферы, заказы, комиссии, payout и ledger.
10. Переключить backend на восстановленную базу и выполнить smoke-тест.

Нельзя удалять исходную базу до завершения проверки восстановленной копии.
Восстановление поверх production допускается только по отдельной процедуре
этапа 5D с явным подтверждением оператора.
